## How to work this queue

- **P0:** resolve before stable acceptance; possible loss of edits or persistent pin state. Priority is a release gate, not a vulnerability severity rating.
- **P1:** required feature completion, reliability, testing or release work from the brief.
- **P2:** optional enhancements explicitly suggested by the brief, or further polish. May be deferred with a documented decision.
- **Agent:** implementation, automated tests and instrumentation. **User:** interactive acceptance on available hardware/apps. **Shared:** both. User testing instructions are in [USER-TESTING.md](docs/USER-TESTING.md).
- Every unchecked entry is open. Check an entry only after its acceptance criteria have evidence; record commit, test result, environment and limitations. Unsupported receiver behavior should be documented explicitly, rather than claimed as supported.
- Complete fixes and automated regressions before asking the user to repeat affected acceptance tests. Do not run the pointer-moving desktop self-test during normal work without arranging an idle desktop.

## Testing findings driving the next fixes

- **Dock blocker (Q49/Q16/Q18):** multiple captures cause visible glitching on first hover before settling. Moving toward the top image exits the effective hover area and collapses the dock, making that capture unreachable.
- **U03 failures (Q16/Q15):** without selection, pointer leave collapses normally. With selections, leaving keeps up to three captures visible; re-entering instantly collapses the dock while selections persist. Alt-reorder works asymmetrically: moving 1 to 2 requires dropping on 3, while moving upward accepts the adjacent item. Delete and Enter did not work; dismiss and click-to-edit did.
- **U02 order observation (Q50):** selecting 3, 2, 1 delivered 1, 2, 3, matching the PiP preview rather than selection-click order. Latest capture is numbered 1; earlier captures shift down. Correct single-image drag was reported. This needs an explicit ordering contract, not an unsupported assumption that click order is required.
- **U04 Save uncertainty (Q21):** editor functions were reported successful, but Save produced no image in the configured export directory. Save As opened that directory. Source confirms Save currently applies/copies the managed capture; this is a discoverability/semantics issue, with export failure handling still requiring verification.
- **Reported successes:** U01 focus/latest-image paste/cancellation and U05 OCR worked as expected. U06 required Windows Print Screen interception to be off. Preserve these results while tracking remaining coverage; do not close broad gates from partial reports.

## M2/M5/M8 — data preservation first

- [ ] **Q02 · P0 · Agent — Make editor close and Exit failure-safe.** `EditorWindow.Closing` invokes apply through an error-swallowing wrapper and starts clipboard work without awaiting shutdown. A failed cache write can close the editor and lose changes. Make close/Exit await or coordinate pending work, retain the editor on apply failure, and offer a clear retry/discard path. Test locked clipboard, unwritable storage, multiple editors and Exit during apply; no silent loss or premature success.
- [ ] **Q03 · P0 · Agent — Complete corrupt-history recovery.** `CaptureRepository` preserves corrupt `history.json`, blocks cleanup and writes `history-recovered.json`, but subsequent starts still read the corrupt original. Provide a safe recovery/confirmation flow which preserves possible old pins and restores new pin/transfer metadata across restart. Test corrupt, truncated, oversized and newer-version metadata across two or more launches. Cleanup must remain conservative until recovery succeeds.
- [ ] **Q04 · P1 · Agent — Lease detached pins and refresh their images.** `PinWindow` does not hold a storage lease. Unpinning its record elsewhere can allow cleanup while the window remains usable. Hold/release leases for open pin views and propagate edited image changes to all views. Test unpin + clear/expiry, editing a detached capture, return-to-dock and closing a pin.
- [ ] **Q05 · P1 · Agent — Restore expired captures to the shelf correctly.** History currently only clears `Dismissed`; shelf visibility still uses the original capture timestamp. Introduce separate visibility/restoration time without changing historical capture time. Restoring an expired capture must show it immediately and honor the newly started shelf lifetime.
- [x] **Q06 · P1 · Agent — Recover orphan metadata and bound history growth.** Recovery currently records dimensions as 1×1 and considers at most 2,000 orphan files; history writes are unbounded while reads reject files over 4 MB. Recover valid dimensions lazily, define bounded/paged history and safe metadata compaction, and preserve pins/transfer protection. Test hundreds/thousands of captures, retention=never and crash-created orphans without slowing ordinary capture or triggering self-generated corrupt-state recovery.
- [ ] **Q07 · P1 · Agent — Make capture/storage/settings failures recoverable.** Cover PNG success followed by metadata failure, replace failure, permission/disk-full errors, partial settings/startup application and invalid custom cache paths. A nonessential history failure should not unnecessarily prevent available pixels reaching the clipboard/dock. Report fallbacks clearly; preserve consistent state and retryable changes. Add fault injection around persistence rather than damaging the user's real cache.
