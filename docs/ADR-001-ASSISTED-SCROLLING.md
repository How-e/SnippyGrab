# ADR 001 — bounded assisted vertical capture (F08)

Decision: **GO for F09's narrow, user-assisted static viewport workflow**, authorized by the 2026-10-09 request to complete the remaining queue. No automatic scrolling, DOM access, browser extension, recording or universal application claim. This is a technical implementation decision; physical/application acceptance remains separate.

The user selects a physical viewport inside one visible application window, explicitly trims a sticky header/footer if needed, captures the first frame, scrolls themselves and explicitly captures the next. The app hides its controls/shelf/pins, restores the selected target, checks its HWND/window bounds/DPI and display topology, then captures the fixed physical rectangle without cursor. A changed/disappeared/minimized target or failed foreground restore cancels the session. Internal application viewport changes cannot be inferred from HWND bounds; the user must cancel/reselect after sidebar/layout changes.

State: selecting → first frame/trim → capturing next → pending seam → accept/reject → repeat → finish or cancel. One session at a time; one pending frame. Escape/close requests cancellation; late worker results are ignored. No automatic wheel/keyboard injection or scroll-position restoration. Frames stay in an owned session directory and never enter history/clipboard individually. Only Finish creates a managed PNG and opens the normal editor. Original captures remain unchanged.

Algorithm: compare old-frame tail and next-frame head using bounded luminance samples across rows/columns, coarse overlap search (at most 512 candidates) then pixel refinement near the best coarse result. Sampling bounds work independently of full image size. Reject flat content, high mean absolute error (>2 gray levels), or ambiguous separated candidates (best/runner margin <3). Exact full pixel equality indicates no progression; a sampled equality alone does not. Repeated rows and fractional/animated changes must remain uncertain. OCR is not alignment authority. A previewed manual integer overlap is available; uncertain/manual seams require explicit confirmation. Reject and remove-last-join make decisions reversible. Sticky regions use explicit, previewed top/bottom cropping fixed before the next frame, never silent deduplication.

Initial budgets: viewport ≤8 MP and each axis ≤4096; ≤30 frames; ≤10 minutes; ≤256 MiB staged PNG bytes. Matching keeps two decoded frames (≤64 MiB BGRA before conversion overhead). Final output uses F07's 80 MP/32767-axis ceiling plus its tighter estimated 256 MiB image budget. Rendering loads sources serially; image encoding is noninterruptible but cancellation is checked before commit. No background capture/polling; expiration is checked on commands. Session crash leftovers are swept on the next session start only, after 24 hours and only with the expected ownership marker, filename inventory and no redirects/subdirectories.

Fixtures: a deterministic document with unique numbered/colored rows and exact shifts must reconstruct every row once; identical frames stop progression; constant regions and periodic repeated rows remain uncertain; noisy/fractional shifts exceed the confidence test; explicit sticky trims must preserve the chosen content; changed sizes reject; undo/reject/cancel/timeout/quota/overflow fail without managed output. Pixel fixtures prove synthetic joins, not arbitrary target compatibility.

First acceptance targets available on this host: Chrome `154.0.8037.98` or Edge `154.0.4258.62`, using a locally generated static numbered HTML document, and Windows Notepad file version `10.0.26100.8457` using static numbered text. Version presence was inspected; physical scrolling acceptance is **NOT RUN**. Virtualized/live chats, animated logs, spreadsheets (especially frozen panes/horizontal scrolling), protected/occluded content, fractional browser zoom and HDR are unsupported first-release targets. Other applications/environments are NOT AVAILABLE until observed.

Why this is feasible: explicit frame collection avoids uncertain automation of arbitrary application scrolling; bounded candidates and session storage limit resource growth; uncertainty is visible and correction stays under user control. Edge/structure matching may improve future confidence but adds complexity; it is deferred until the deterministic matcher and actual target corpus demonstrate a need. If the implementation cannot satisfy these bounds/uncertainty rules, F09 must remain conditional.
